# recipes.db → PostgreSQL: the ETL (`pgmigrate/`)

*2026-11-09. Follows `docs/postgres-migration-inventory.md` (what is SQLite-specific
and why) and the sequence decided 2026-10-17 (clone first, soak, THEN Postgres on
the clone). The clone has been primary since 10-23 with clean nightlies, so the
soak condition is met; this is the first build step. Status: **ETL BUILT and
verified against a scratch PostgreSQL 17 on MARLEY_SVR. Nothing in the app reads
Postgres yet.***

## What it is

One package, three stages, re-runnable:

```
python -m pgmigrate plan   --sqlite recipes.db [--ddl out.sql] [--no-vector]
python -m pgmigrate run    --sqlite recipes.db --dsn postgresql://... --drop
python -m pgmigrate verify --sqlite recipes.db --dsn postgresql://...
```

`plan` introspects SQLite and prints what will be built (tables, jsonb columns,
embedding columns, what dissolves) and can write the full DDL. `run` builds the
schema, COPYs every base table, creates indexes, fills the full-text columns,
installs triggers, ANALYZEs, then verifies. `verify` compares the two engines and
exits non-zero if a row count or a generated column differs. The DSN comes from
`--dsn` or `BCC_PG_DSN`. `--drop` is `DROP SCHEMA public CASCADE` on the target:
without it a re-run fails on the first existing table rather than merging.

Scope: **recipes.db only.** page_cache.db, training.db and media.db stay SQLite
and move as files (inventory §"The estate").

## The rules (translate.py)

| SQLite | PostgreSQL | note |
|---|---|---|
| INTEGER / REAL / TEXT / BLOB | bigint / double precision / text / bytea | no column in recipes.db holds a value outside its declared affinity (measured over all 61 tables) |
| single `INTEGER PRIMARY KEY` | `bigint GENERATED BY DEFAULT AS IDENTITY` | explicit ids still insert; sequences are set past max(id) after the load |
| TEXT column whose every non-null value is a JSON object/array | `jsonb` | detected from the data, not declared (49 columns in 26 tables); a column mixing `''` with documents stays text and is listed by `plan` |
| BLOB `embedding` (6144 bytes = 1536 float32) | `vector(1536)` | needs pgvector; without it `real[]` and no index, and `plan`/`run` say so loudly |
| ISO-timestamp TEXT (111 columns, 7 formats, some naive) | stays `text` | deliberately: a type change here is an app-write-path change, phase 2 |
| `GENERATED ... VIRTUAL` (24 on recipes, 26 on master_recipes) | `GENERATED ... STORED` | `json_extract(data,'$.a.b')` → `(data #>> '{a,b}')`, wrapped in `bcc_to_num()` / `bcc_to_int()` for REAL / INTEGER targets so SQLite's affinity rules survive (`true`→1, non-numeric→NULL instead of an insert error) |
| the ~12 KB `source_host` CASE tree | `bcc_source_host(url)` | scheme stripped, cut at `/`, cut at `?`, leading `www.` dropped, lower-cased; verified identical on all 14,715 rows |
| expression indexes on `json_extract` | expression indexes on `#>>` | app predicates must be written as `data #>> '{a,b}' = %s` to hit them |
| partial indexes | same | `WHERE` carried through the same translator |
| `bcc_sortkey()` (Python callback) | `bcc_sortkey(text)` IMMUTABLE SQL function | `lower(unaccent(translate(typographic→ascii)))`; see the measurement below |
| fts5 tables + 6 triggers | one `fts tsvector` column per recipe table, GIN index, one BEFORE INSERT/UPDATE OF data trigger | weights A name+dish · B author+domain · C ingredients · D cuisine (the inventory's four classes); text search config `bcc` = english + unaccent |
| vec0 tables + 3 cleanup triggers | nothing | the embedding lives on the base table; HNSW cosine index on dishes, master_recipes, products when pgvector is present |

Identifiers are quoted in the DDL; every name in recipes.db is lower-case, so
unquoted app SQL keeps working.

## The first run (2026-11-09, scratch PG 17.6 on MARLEY_SVR, no pgvector)

| check | result |
|---|---|
| rows copied | 749,486 in 61 tables, 52 s end to end |
| row counts | 61/61 match |
| generated columns | 24 on recipes × 487 rows, 26 on master_recipes × 14,228 rows: **0 mismatches** |
| `bcc_sortkey` order of 14,228 master names | 13 inversions (0.09%), all ONE name: "Cacık" — unaccent folds the Turkish dotless ı to i and files it with the "Cacik" rows, NFKD leaves ı alone and SQLite files it after "Cacio e Pepe". The browser's ICU order agrees with Postgres here; the server's own fold is already 26 inversions from ICU, so this is inside the noise it accepted |
| full-text hit sets, SQLite MATCH vs `@@ plainto_tsquery('bcc')` | first pass: lemon chicken 441/439 · shrimp 449/447, the misses being ingredients like "vegetable/chicken broth" that fts5 splits at `/` and the Postgres parser keeps as one `file` token. Fixed in `bcc_recipe_fts` (slashes → spaces in the ingredient text); béchamel 35/35 · kenji 76/76 · banana bread 73/73 · nytimes 346/346 were already exact |
| embeddings | 6 columns, every non-null count equal; KNN check skipped (no pgvector) |

Preflight found nothing to warn about: no TEXT in numeric generated columns, no
NUL bytes, every embedding exactly 1536 float32, every JSON column valid over all
rows.

## What this is NOT yet

* **Not the app port.** Inventory "REWRITE" items 1–7 are all still owed: `?`→`%s`,
  `lastrowid`→`RETURNING`, `json_extract`→`#>>`, `INSERT OR REPLACE`→`ON CONFLICT`,
  jsonb columns come back as dicts (every `json.loads(row["data"])` must stop
  decoding), fts5 MATCH grammar (`_fts_query`) → tsquery, bm25 tiers → weight
  classes, `temp.q_match` → CTE or temp table, PRAGMA census. That is a separate
  branch behind the step-0 factory (`input/pipeline/db.connect`) with a
  `DB_BACKEND` switch.
* **Not pgvector-tested.** The PG 17 on this box has no `vector` extension. The
  target is PostgreSQL 18 on MARLEY_SVR with pgvector installed (the Windows
  pgvector build matches the PG major). Until then every run reports the
  `real[]` fallback.
* **Not a backup chain.** `backup_db.py`, the nightly bat, the standby sync and
  the DR doc all assume a file; that redesign (pg_dump/pg_restore, or a streaming
  standby on BAILEY) is its own step.

## Running the scratch cluster again

The verification above used a throw-away cluster that any user can create
without admin rights (PG 17 binaries are already on the box):

```
"C:\Program Files\PostgreSQL\17\bin\initdb" -D <dir> -U bcc -A trust -E UTF8 --locale=C
echo port = 54329 >> <dir>\postgresql.conf
"C:\Program Files\PostgreSQL\17\bin\pg_ctl" -D <dir> -l <dir>\server.log start
"C:\Program Files\PostgreSQL\17\bin\psql" -h 127.0.0.1 -p 54329 -U bcc -d postgres -c "create database bcc_etl"
python -m pgmigrate run --dsn postgresql://bcc@127.0.0.1:54329/bcc_etl --drop
```

`pip install "psycopg[binary]"` is the only new dependency (3.3.8 installed in the
venv on 2026-11-09).
